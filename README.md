# 衣橱穿搭小程序

拍下衣服收进衣橱 → 按天气自动给出穿搭建议 → 还能和 AI 聊着搭。

- 登录后使用，每个账号的衣橱数据相互独立
- 微信一键登录 + 手机号验证码登录 / 注册
- 拍照或相册上传单品，支持分类、颜色、季节、标签
- 按日期 + 城市的天气，从**已上传的单品**里自动挑搭配
- AI 对话式穿搭：围绕某件单品、某个场合继续追问

## 技术栈

| 层 | 选型 |
|---|---|
| 前端 | 微信原生小程序（WXML / WXSS / JS，无框架） |
| 后端 | WorkBuddy 云服务（免自建服务器）：云数据库 + 用户认证 + 文件存储 + 免密钥大模型 |
| 设计 | 紫白主色 + 清新绿行动按钮 + 大圆角卡片 |

**不需要你自己准备服务器。** 数据库、登录、图片存储、AI 调用都由云服务托管。

## 开发者工具里运行

1. 用微信开发者工具「导入项目」，选择本目录。
2. `appid` 先用 `touristappid`（游客模式）即可浏览界面；`wx.login` 相关能力需绑定真实小程序后才能验证。
3. 若修改了依赖，执行「工具 → 构建 npm」重新生成 `miniprogram_npm/`。

静态自检：

```bash
node tests/smoke.js
```

## 数据表（云数据库，自动按账号隔离）

| 表 | 用途 |
|---|---|
| `garments` | 衣物单品：名称、分类、标签、颜色、季节、图片路径 |
| `outfit_records` | 收藏的穿搭方案 |
| `chat_messages` | AI 对话记录（按会话归并） |
| `user_settings` | 昵称、常驻城市 |

每张表都开启了行级安全（RLS），`owner_id` 由数据库按当前登录身份自动填充，前端不传也不能改，账号之间无法互相读写。

> 城市为 `text`：可存中文城市名，用于天气穿搭定位。

## 关于天气

小程序只能请求「request 合法域名」白名单内的地址。托管发布时平台会自动登记云服务网关域名，但不会登记第三方天气接口。因此 `utils/weather.js` 采用三级策略：

1. **手动设置**（最高优先级）：在首页天气卡点「手动」，选天气 + 温度区间；
2. **真实天气接口**：把 `utils/weather.js` 里的 `PROVIDER.url` 换成你自己的天气接口，并在微信公众平台「开发管理 → 服务器域名」加入 request 合法域名；
3. **AI 气候估算**（默认兜底）：未配置接口时，用云端大模型按城市与日期的气候常识估算典型天气，来源会标注为「AI 估算」。

不论天气来自哪一级，穿搭建议都由大模型结合**你衣橱里真实存在的单品**生成。
