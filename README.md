# 衣橱穿搭小程序

拍下衣服收进衣橱 → 按天气自动给出穿搭建议 → 还能和 AI 聊着搭。

- 登录后使用，每个账号的衣橱数据相互独立
- 微信一键登录 + 手机号验证码登录 / 注册
- 拍照或相册上传单品，支持分类、颜色、季节、标签
- 按日期 + 城市的天气，从**已上传的单品**里自动挑搭配
- AI 对话式穿搭：围绕某件单品、某个场合继续追问

## 技术栈

| 层 | 选型 |
|---|---|
| 前端 | 微信原生小程序（WXML / WXSS / JS，无框架） |
| 后端 | WorkBuddy 云服务（免自建服务器）：云数据库 + 用户认证 + 文件存储 + 免密钥大模型 |
| 设计 | 紫白主色 + 清新绿行动按钮 + 大圆角卡片 |

**不需要你自己准备服务器。** 数据库、登录、图片存储、AI 调用都由云服务托管。

## 开发者工具里运行

1. 用微信开发者工具「导入项目」，选择本目录。
2. `appid` 先用 `touristappid`（游客模式）即可浏览界面；`wx.login` 相关能力需绑定真实小程序后才能验证。
3. 若修改了依赖，执行「工具 → 构建 npm」重新生成 `miniprogram_npm/`。

静态自检 + 单测：

```bash
npm test          # 等价于 node tests/units.js && node tests/smoke.js
node tests/smoke.js
node tests/units.js
```

## 数据表（云数据库，自动按账号隔离）

| 表 | 用途 |
|---|---|
| `garments` | 衣物单品：名称、分类、标签、颜色、季节、图片路径 |
| `outfit_records` | 收藏的穿搭方案 |
| `chat_messages` | AI 对话记录（按会话归并） |
| `user_settings` | 昵称、常驻城市 |

每张表都开启了行级安全（RLS），`owner_id` 由数据库按当前登录身份自动填充，前端不传也不能改，账号之间无法互相读写。

> 城市为 `text`：可存中文城市名，用于天气穿搭定位。

## 关于天气（速度优先）

小程序只能请求「request 合法域名」白名单内的地址。托管发布时平台会自动登记云服务网关域名，但不会登记第三方天气接口。`utils/weather.js` 默认接入**腾讯位置服务**（域名 `apis.map.qq.com`，已备案、无需自建中转），按「从快到慢」分三级取数：

1. **缓存命中**：同一城市 + 同一日期在有效期内直接返回（毫秒级）。
2. **本地气候估算**（兜底）：`utils/climate.js` 内置全国气候区数据（月均温 + 雨季），**同步计算、离线可用、毫秒级返回**，来源标注「气候估算」。
3. **后台精修（腾讯实时天气）**：页面拿到结果后立刻上屏，同时在后台调用腾讯天气接口（`/ws/weather/v1/`，按城市 adcode 查询，今天用 `type=now`、未来用 `type=future`），成功则静默替换，来源标注「实时」；接口未配置 key 或调用失败时回退到大模型气候估算（来源标注「AI 精修」）。

手动设置的天气优先级最高，且直接落缓存。

打开小程序时会**自动按「常驻城市 + 当前选择日期」取一次天气**（`app.js` 预热 + 首页 onShow 自动刷新），切换城市或切换日期也会自动重新获取。

启用腾讯实时天气（两步）：
- 在 `utils/config.js` 填入 `TENCENT_LBS_KEY`（去 https://lbs.qq.com 申请 WebServiceAPI key，并在该 key 的「授权 AppID」里填入本小程序 AppID）；
- 在微信公众平台「开发管理 → 服务器域名 → request 合法域名」加入 `https://apis.map.qq.com`（免费额度 6000 次/日，非商业）。

不论天气来自哪一级，穿搭建议都由大模型结合**你衣橱里真实存在的单品**生成。

## 标签与交叉分类

- 标签来源三合一：内置预设 + 自己添加的自定义标签（本地持久化，带 ✕ 可删）+ 衣橱里已经用过的标签。
- 一件单品可以同时挂**多个标签**（交叉分类）。
- 衣橱页支持**多标签交叉筛选**：选中多个标签时，只显示同时命中全部标签的单品；可与分类、关键词叠加使用。
